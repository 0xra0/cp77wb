# v0.5 live spatial authoring

v0.5 moves cp77wb's optional CET bridge from basic live transforms to spatial operations that reuse World Builder's own editor APIs and history.

## Capability gate

Always begin with:

```bash
cp77wb live "$RPC" ping
cp77wb live "$RPC" history
cp77wb live "$RPC" raycast --ray-mode camera
```

A write is allowed only when the bridge can prove that `modules/utils/history` belongs to the same `spawnedUI` as `GetMod("entSpawner").baseUI.spawnedUI`. Scene raycasts similarly require World Builder's active `modules/utils/editor/editor` singleton.

## Protocol v3

New spatial operations use `cp77wb-live/3`:

- `raycast_scene`
- `scale_selection`
- `snap_selection`
- `batch_transform`
- `surface_scatter`
- `save_roots`
- `reload_root`

Older read calls remain compatible with v1/v2 where possible. v0.4-era writes remain accepted through v2 on a v0.5 bridge, but new spatial writes are never silently downgraded.

## Scene raycast

Camera ray:

```bash
cp77wb live "$RPC" raycast --ray-mode camera
```

Custom ray:

```bash
cp77wb live "$RPC" raycast --ray-mode custom \
  --origin-x 0 --origin-y 0 --origin-z 10 \
  --dir-x 0 --dir-y 0 --dir-z -1
```

The bridge calls World Builder's `editor.getRaySceneIntersection()` rather than implementing its own collision query. This lets it resolve WB node intersections and, when requested, physical `PlayerBlocker` hits using the same path as the editor.

## Live scale

```bash
cp77wb live "$RPC" scale --uniform 1.2
cp77wb live "$RPC" scale --uniform 1.2 --apply
```

Non-uniform scale:

```bash
cp77wb live "$RPC" scale --scale-x 1.2 --scale-y 0.8 --scale-z 1.0 --apply
```

Optional world-space pivot:

```bash
cp77wb live "$RPC" scale --uniform 0.9 \
  --pivot-x 100 --pivot-y 200 --pivot-z 12 --apply
```

The transform scales child positions around the pivot and scales only spawnables that already expose a scale field. Strict mode refuses a selection containing an unscaleable spawnable. `--allow-partial` allows the positional portion while leaving unsupported object scale unchanged.

## Surface snap

```bash
cp77wb live "$RPC" snap
cp77wb live "$RPC" snap --apply
```

A custom direction can be supplied with `--dir-x`, `--dir-y`, `--dir-z`. The bridge calls each selected element's native `dropToSurface(false, direction)` method. Any temporary history records created by WB internals are replaced with one pre-change transaction snapshot.

## Batch transaction

`batch` accepts a JSON array of `move`, `rotate`, `scale` and `snap` operations. Successful execution is committed as one history action.

Example:

```json
[
  {"type":"move","x":2,"z":0.5},
  {"type":"rotate","yaw":15},
  {"type":"scale","x":1.05,"y":1.05,"z":1.05},
  {"type":"snap","direction":{"x":0,"y":0,"z":-1}}
]
```

```bash
cp77wb live "$RPC" batch --ops-file ops.json
cp77wb live "$RPC" batch --ops-file ops.json --apply
```

If any operation throws, cp77wb asks the saved WB history snapshot to restore the pre-transaction selection state and does not commit a new history action.

## Reference-aware live duplicate

v0.4 refused live duplication if NodeRefs were present. v0.5 can clone those subtrees safely by default:

1. clone through the WB element model;
2. let WB assign a unique sibling name;
3. refresh `spawnedUI.paths` and the real NodeRef registry;
4. generate a fresh NodeRef for every NodeRef-defining spawnable;
5. remap known internal NodeRef references;
6. repair `outlinePath` references when they target a path inside the copied subtree;
7. commit all copies as one insert history action.

`--keep-noderefs` exists only for specialized cases and should normally be avoided.

## Surface-aware scatter

Surface scatter requires exactly one selected root object/group:

```bash
cp77wb live "$RPC" surface-scatter \
  --count 20 --half-x 8 --half-y 5 --seed 42 --apply
```

The random generator is deterministic for a given seed. Each clone is offset, optionally yaw-randomized, then passed through the same native `dropToSurface()` path. New NodeRefs are generated by default. All clones become one insert history action.

## Save/reload

```bash
cp77wb live "$RPC" save --apply
cp77wb live "$RPC" reload --path /MyBuild --apply
```

`save` calls the `save()` method of active top-level WB roots. `reload` is restricted to a top-level saveable root, loads `data/objects/<fileName>.json` through World Builder's config loader, replaces the active root, and creates an undoable remove+insert action.

## What v0.5 deliberately does not do

- no arbitrary live editing when World Builder history cannot be proven;
- no physics implementation independent of World Builder;
- no automatic modification of World Builder source files;
- no silent duplicate NodeRefs;
- no background mutation or unattended apply; the caller must use `--apply` / `apply=true`.
